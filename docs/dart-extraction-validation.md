## 원인과 수정 범위

기준 main은 `47ccf54c2c1999b0f3fc32f6f5b4546e103d4ab0`이다. 이 버전의 dart.json/dart_numeric.json은 비어 있지만 scoop.json에는 이전 12건 중 성공 7건·실패 5건의 진단이 남아 있다. 실패 대상은 이전 커밋 `f290eed`의 dart_numeric.json에서 복원했다. 운영 JSON은 변경하지 않았다.

실패 5건의 공개 DART 뷰어를 동일 코드로 재조회한 결과, 모두 본문을 받았지만 기존 추출기는 수치를 찾지 못했다. 4건은 값과 단위가 다른 표 셀에 있어 평탄화된 본문의 정규식으로 추출되지 않았다. 나머지 1건은 이사회의사록 등 증빙서류의 날인 변경으로, 원문에 추출할 금액이 없다.

`dart_numeric_extractor.py`의 `extract_table_facts`를 추가했다. 확인된 항목명, 바로 옆 숫자 셀, 명시된 단위만 결합한다. 항목 머리글 단위와 바로 앞 단위 전용 표를 지원하고, 단위를 다른 표·문서로 전파하지 않는다. 원문 항목명·행·출처를 numericFacts에 보존한다. 생산중단·영업정지 관련 매출은 손실액이나 신규 계약금액이 아니라는 해석 주의도 함께 기록한다.

`fetch_dart_viewer_text`, `extract_viewer_facts`, `extract_document`에 표 추출을 연결하고, 뷰어 목차 진단의 잘못 이스케이프된 정규식을 수정했다. 첨부 정정 제목과 본문의 증빙서류 정정 대상이 모두 확인된 무수치 문서는 별도 상태로 분류한다. 상위 API 오류는 upstreamError에 보존한다. `main`은 이 상태에 과거 캐시 금액을 붙이지 않는다. 점수·출입처·단독 후보 필터는 수정하지 않았다.
