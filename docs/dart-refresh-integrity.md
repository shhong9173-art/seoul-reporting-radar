## 확인한 원인

- `dart_collector.main`은 API 키 누락·기업 코드 실패·기업별 조회 실패 때도 빈 목록을 운영 파일에 저장하고 정상 종료했다. 일부 기업만 성공한 경우도 전체 갱신처럼 저장했다.
- `dart_numeric_extractor.main`도 오류가 있는 빈 목록 또는 누락된 입력을 빈 수치 파일로 덮었다.
- Auto Desk는 DART 파일을 갱신하지만 scoop 후보를 다시 생성하지 않는다. scoop에 저장된 sourceHealth는 이전 값으로 남아 있었다. 프런트엔드는 이 이전 진단을 그대로 표시했다.
- 기존 화면은 정상적인 관련 공시 0건도 수집 오류라고 표시했다. 수치 추출 대상 12건을 전체 공시 목록 건수로 표현한 문구도 부정확했다.

## 수정

- `dart_collector.py`: 목록 조회 오류·부분 실패 때 기존 파일을 보존하고 실패 종료한다. API status 013은 정상적인 빈 결과로 인정한다. 잘못된 목록 구조와 미조회 후속 페이지는 실패 이유로 구분한다. 성공한 결과만 임시 파일을 거쳐 교체한다. 예외 로그에는 요청 URL에 들어갈 수 있는 API 키를 출력하지 않는다.
- `dart_numeric_extractor.py`: 오류·누락 입력에서 기존 수치 파일을 보존한다. 성공 출력에는 생성 시각과 실제 입력 전체의 SHA-256을 남긴다. 정상 0건은 그대로 반영한다.
- `dart_health.py`: 현재 목록·수치 파일로 진단을 다시 계산한다. 후보·원래 생성 시각은 변경하지 않는다. 후보 생성 시 사용한 입력 해시와 현재 입력의 일치 여부를 표시한다. 과거 파일처럼 해시가 없으면 일치한다고 추정하지 않고 unverified로 처리한다.
- `scoop_scout.py`: 후보 생성 완료 시 입력 해시와 진단을 기록한다.
- `scoop.js`: 정상 0건·오류·부분 실패·분석 입력 불일치를 구분한다. 수치 추출 대상 건수와 전체 목록 건수를 혼동하지 않도록 문구를 수정했다.
- 두 워크플로: Auto Desk 게시 전 및 두 배포 작업에서 실제 배포할 파일의 진단을 갱신한다. Auto Desk의 수치 추출 실패 무시를 제거하고 기존 공식 수집기 테스트를 추가했다. 배포 경로·일정·사이트 구조는 변경하지 않았다.

## 제한과 운영상 영향

API 키가 없어 새로운 OpenDART 실접속 수집은 수행하지 못했다. 과거 실제 운영 파일 재현과 API 응답 모의 테스트를 수행했다. GitHub Actions 실행·사이트 배포·운영 화면 반영은 미검증이다.

이 변경은 DART 일부 조회가 실패하면 해당 Auto Desk 갱신 전체의 게시를 보류한다. 기존 게시물은 유지되지만 뉴스 갱신도 늦어질 수 있다. 실패한 자료를 정상 최신 데이터로 게시하지 않기 위한 보수적인 처리다. 장기적으로는 DART 장애 상태를 따로 게시하면서 정상 뉴스만 독립 갱신하는 구조를 검토해야 한다.

현재 첫 목록 페이지까지만 수집한다. 후속 페이지가 있으면 이를 숨기지 않고 실패 처리한다. 페이지 순회와 재시도 개선은 별도 작업이다. 기업 코드 목록 자체의 취재 범위 완전성은 이번 범위 밖이다. 두 수집 워크플로의 동시 실행 구조는 유지하므로 후보 재분석 사이에 입력이 달라질 수 있으며, 이때 일치 여부 경고로 구분한다. 실패 종료 직후 웹에 새 장애 로그를 게시하지는 않으며 상세 실패 사유는 Actions 로그에서 확인해야 한다.
