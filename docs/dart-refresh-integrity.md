# DART 갱신 무결성 검증 (2026-10-12)

기준 main: `8aafac0a930d30d69cdb0a84e6aab7f1080166c3`.

## 확인한 원인

- `dart_collector.main`은 API 키 누락·기업 코드 실패·기업별 조회 실패 때도 빈 목록을 운영 파일에 저장하고 정상 종료했다. 일부 기업만 성공한 경우도 전체 갱신처럼 저장했다.
- `dart_numeric_extractor.main`도 오류가 있는 빈 목록 또는 누락된 입력을 빈 수치 파일로 덮었다.
- Auto Desk는 DART 파일을 갱신하지만 scoop 후보를 다시 생성하지 않는다. scoop에 저장된 sourceHealth는 이전 값으로 남아 있었다. 프런트엔드는 이 이전 진단을 그대로 표시했다.
- 기존 화면은 정상적인 관련 공시 0건도 수집 오류라고 표시했다. 수치 추출 대상 12건을 전체 공시 목록 건수로 표현한 문구도 부정확했다.

## 수정

- `dart_collector.py`: 목록 조회 오류·부분 실패 때 기존 파일을 보존하고 실패 종료한다. API status 013은 정상적인 빈 결과로 인정한다. 잘못된 목록 구조와 최대 5페이지를 순회하며 뒤 페이지 실패·페이지 변동·상한 초과는 미완료로 구분한다. 타임아웃·연결 오류·HTTP 502/503/504는 한 번 재시도하며 인증 오류는 재시도하지 않는다. 성공한 결과만 임시 파일을 거쳐 교체한다. 예외 로그에는 요청 URL에 들어갈 수 있는 API 키를 출력하지 않는다.
- `dart_numeric_extractor.py`: 오류·누락 입력에서 기존 수치 파일을 보존한다. 성공 출력에는 생성 시각과 실제 입력 전체의 SHA-256을 남긴다. 정상 0건은 그대로 반영한다.
- `dart_health.py`: 현재 목록·수치 파일로 진단을 다시 계산한다. 후보·원래 생성 시각은 변경하지 않는다. 후보 생성 시 사용한 입력 해시와 현재 입력의 일치 여부를 표시한다. 과거 파일처럼 해시가 없으면 일치한다고 추정하지 않고 unverified로 처리한다.
- `scoop_scout.py`: 후보 생성 완료 시 입력 해시와 진단을 기록한다.
- `scoop.js`: 정상 0건·오류·부분 실패·분석 입력 불일치를 구분한다. 수치 추출 대상 건수와 전체 목록 건수를 혼동하지 않도록 문구를 수정했다.
- `dart_refresh.py`: 목록·수치 갱신을 하나의 단위로 실행한다. 어느 단계든 실패하면 두 파일을 모두 이전 바이트로 복구하고 별도 상태 파일에 실패 단계·조회 시각을 기록한다. 유효한 이전 파일이 있는 경우에만 정상 뉴스 갱신을 계속한다. 예외 메시지의 URL·키는 상태 파일에 기록하지 않는다.
- 두 워크플로: Auto Desk 게시 전 및 두 배포 작업에서 실제 배포할 파일의 진단을 갱신한다. Auto Desk의 수치 추출 실패 무시를 제거하고 기존 공식 수집기 테스트를 추가했다. 배포 경로·일정·사이트 구조는 변경하지 않았다.

## 제한과 운영상 영향

API 키가 없어 새로운 OpenDART 실접속 수집은 수행하지 못했다. 과거 실제 운영 파일 재현과 API 응답 모의 테스트를 수행했다. GitHub Actions 실행·사이트 배포·운영 화면 반영은 미검증이다.

DART 갱신 실패 때는 유효한 이전 목록·수치 파일이 있으면 둘을 함께 복구하고 정상 뉴스 갱신을 계속한다. 장애 상태는 dart_refresh_status.json으로 별도 게시되며 화면에 마지막 자료 생성 시각과 최근 조회 시도를 구분한다. 유효한 이전 파일이 없거나 손상됐으면 전체 게시를 중단한다. 이번 실행에서 운영 JSON을 변경한 것은 아니다.

공식 [공시검색 API 문서](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001)의 page_no·total_page 구조를 확인했다. 최대 5페이지를 순회하며 상한 초과 또는 조회 도중 페이지 수가 바뀌면 불완전 수집으로 표시한다. 더 많은 페이지·목록 변화에 대한 재수집은 후속 과제다. 기업 코드 목록 자체의 취재 범위 완전성과 오래된 후보 자동 숨김은 이번 범위 밖이다.

추가 검증: API 키가 없는 실제 로컬 환경에서 운영 파일의 격리 사본으로 dart_refresh.py를 실행했다. 목록 갱신 실패 상태를 기록하면서 두 원본 파일의 바이트가 유지되는지 확인했다. 이는 OpenDART 실접속 성공 검증이 아니다.
