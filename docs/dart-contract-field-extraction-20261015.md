# DART 공급계약·정정 공시 원문 XML 표 항목 추출

## 문제

2026-10-15 기존 공식 OpenDART `document.xml` 수집에서 공급계약 등 7개 공개 사건의 원문 ZIP을 열었으나, 공급계약의 계약금액·상대방·기간이 `observedFields`에 저장되지 않았습니다. 기존 `tabular_fields`는 셀의 `rowspan`/`colspan`이 하나라도 있거나 3열 표면 전체 행을 건너뛰었습니다. 이는 실제 DART 공시의 `계약내역 / 계약금액(원) / 값` 형식에 취약합니다.

## 개선

- `scripts/dart_contract_tables.py`: OpenDART가 제공한 각 공시 XML 문서의 HTML 형식 TABLE/TR/TD/TH를 독립적으로 읽고, 표의 **명시적 계약금액(원)·상대방·계약시작·계약종료·생산재개일·시설투자금액** 항목만 추출합니다.
- 2열 항목/값, 3열 구분/항목/값, 독립 4열 두 쌍, `계약기간` 표의 2행 rowspan + 시작일·종료일을 지원합니다. 중첩 표는 구분하고 출처와 관계없는 표 주변 문구를 합성하지 않습니다.
- 항목이 다르면 값을 합치지 않습니다. 동일 항목의 값이 2개 이상 서로 다르면 **conflictingDocumentFields**에 포함시키고 확정값을 버립니다.
- `계약금액(원)` 행은 숫자 형식이어야 합니다. 외화 단위가 뒤섞였거나 미정·영업비밀로 비공개된 값은 추출하지 않습니다. 회사·사업장 이름을 화면에 표시할 때도 해당 표에서 직접 확인한 경우만 사용합니다.
- 각 값마다 `sourceLabel`, `rowPattern`, `basis=same_official_table_row`를 남깁니다. 이는 *공식 공시상 기재값*이지 실제 계약 체결·출하·매출 인식·확정된 수주가 아닙니다.
- `scripts/recent_contracts.py`: 원문을 열었으나 추출값이 없을 때 **'0원/계약 없음'이 아니라 '표 구조 확인 필요'**라고 명시. 해당 값의 출처·표수·충돌 상태 포함.
- `scripts/dart_lineage.py`: 원공시가 독립적으로 연결됐을 때만 새 추출기로 전후 원문을 비교하며, 같은 값이 충돌하면 비교 대상에서 제외합니다.
- `scripts/dart_contract_followup.py` 및 `dart-contract-followup.html`: 공식 항목명·구조 증거와 중복 충돌 메시지 제공. 언론 RSS 결과 없음과 기보도 없음은 동일하지 않습니다.

## 안전성 및 한계

1. DART 원문 데이터와 API 호출권한은 기존 승인된 GitHub Secrets로 처리합니다. 키나 원문 인증 URL을 페이지/로그/결과 JSON에 저장하지 않습니다.
2. 현재 실제 공시 원문의 표가 반드시 위 구조 중 하나라고 단정할 수 없습니다. CI 합성 XML 회귀검증 성공과 **실제 OpenDART 수집 성공은 구분**해야 합니다.
3. 원문에 계약금액 수치가 있더라도 계약 상대방·계약기간·물량을 모두 검증했다는 의미가 아닙니다. 특정 제품·설비의 실제 영향은 출입처 회사 또는 추가 공식 자료를 확인합니다.
4. 정정공시는 최초 공시 접수번호가 공식 정정문에 정확히 명시되고 동일 발행 법인·사건 유형·두 원문의 항목이 일치한 경우에만 비교합니다. 동일 날짜·동일 제목 추정 연결은 계속 금지합니다.
5. 숫자 차이는 비교하는 두 원문의 사실일 뿐 계약액 증감이 실적이나 출하량 증가를 뜻하지 않습니다. 계산식과 산업적 귀결을 별도 취재 없이 기사 야마로 쓰지 않습니다.

## 향후 검증 순서

첫 자동수집에서 `digests/recent_contracts_latest.json`의 `observedFields`·`documentTablesExamined`·`conflictingDocumentFields`를 확인하고, 전후 검증 결과가 `digests/dart_contract_followup_latest.json`에 정상 반영됐는지 검사합니다. 7개 공시 중 **모든 값이 계속 빈 경우** 실제 DART XML 표의 레이아웃을 추가 점검해야 하며, 문서 값을 임의 생성하지 않습니다.

특히 공시상 계약상대가 '자회사'·'계열회사'인 경우, **외부 최종 고객/공급 물량/연결 매출 기여를 별도 확인**하도록 질문을 표시합니다. 자회사 대상 공시금액 자체를 그룹 외부의 새로운 계약액과 합산해 기사로 만드는 실수를 예방합니다.
