# NTIS 상세 수집 및 검색어별 조회 배분 개선

## 범위와 원인

사용자의 후속 지시에 따라 우선순위를 판단해 수정·검증·PR까지 진행했다. 예약 실행은 설정하지 않았다. 기준 main은 `47ccf54c2c1999b0f3fc32f6f5b4546e103d4ab0`, 브랜치는 `fix/ntis-official-details`다. IRIS PR #1과 독립적으로 main에 적용할 수 있게 작성했다.

과거 저장 데이터의 상세 타임아웃 4건은 이번 환경에서 재현되지 않았다. 실패 이력이 있던 `roRndUid=1260364`는 HTTP 요청이 HTTPS로 이동해 성공했고 직접 HTTPS도 성공했다. 따라서 HTTP가 과거 장애 원인이었다거나 타임아웃을 근본적으로 해결했다고 주장하지 않는다.

현재 코드에서 확실히 재현한 문제는 **첫 검색어가 상세 조회 한도 8건을 소진하는 구조**다. 철강·변압기·전력망을 검색해도 기존에는 철강의 오래된 자료 8건만 상세 조회했다. 다음 검색어는 목록 요청만 하고 상세를 확인하지 못했다. 기존 `announcementLinks=11`도 발견 가능한 전체 링크 수가 아니라 중간에 루프를 끊은 부분 집계였다.

또 전체 HTML 앞부분을 summary로 사용해 메뉴가 본문을 밀어낼 수 있었다. 검색 결과는 `R&D`를 `RD`로 색인하는 사례가 실제로 확인됐다. 표기 차이를 제외한 실질적인 제목 불일치는 계속 거부한다.

## 변경 파일과 동작

- `pre_scoop_radar.py`: `fetch_direct_ntis_announcements`가 먼저 각 검색어의 목록을 읽고 상세 URL을 중복 제거한 뒤 번갈아 조회한다. 기본 상세 한도 8건과 기존 검색어 순환을 유지한다. 명시적 검색어 전달은 재현 가능한 진단용이다.
- `_ntis_fetch`: 요청당 12초, 일시적인 전송 오류·429·5xx에 1회 재시도. 403 등은 재시도하지 않는다. 실패 이력·요청 횟수·단계·URL을 남긴다. 실제 장애가 반복되면 실패로 보고한다.
- `_ntis_detail_url`: 공식 `www.ntis.go.kr/rndgate/eg/un/ra/view.do`와 실제 숫자 `roRndUid`만 허용하고 HTTPS로 정규화한다. 외부 도메인·중복 ID 파라미터·비숫자 ID를 제외한다.
- `parse_ntis_detail`, `_NtisBodyParser`: 실제 `ditail_tit`, 라벨 필드, `notice_cont`에서 제목·공고일·접수일·마감일·사업명·본문을 추출한다. 사이트 메뉴를 본문 또는 기업 근거로 사용하지 않는다. 없는 공고일·금액은 만들어내지 않는다.
- `_ntis_title_key`: 공백 및 실제 확인한 R&D/RD 표기만 정규화한다. 목록·상세 제목이 다른 경우 수용하지 않는다.
- `tests/ntis_collector_cases.py`: 신규 테스트 16개. `tests/test_official_collectors.py`가 이를 가져오므로 기존 Actions 테스트 명령으로 실행된다.
- `tests/fixtures/ntis/*`: 공식 HTML의 실제 앵커·본문·메타데이터 발췌와 출처 기록.
- `tests/diagnose_ntis.py`: 운영 파일에 쓰지 않고 수집기만 실행해 진단 JSON을 표준출력으로 제공한다.

직접 출입처 화이트리스트·단독 기준·다른 수집기 구현·운영 JSON은 바꾸지 않았다. 공모는 기업 참여나 선정의 증거가 아니다. 기존 기업명 판정 모듈 자체의 별칭/부분일치 문제는 이번 범위에서 재작성하지 않았다.

## 테스트

```text
python -m unittest discover -s tests -p 'test_official_collectors.py' -v
python tests/diagnose_ntis.py 철강 변압기 전력망
```

- Python 3.12: 기존 8개 + 신규 16개 = **24개 통과, 실패 0**.
- 이전 IRIS PR #1과의 가상 병합 트리를 별도 로컬 폴더에 풀어 실행: **39개 통과, 실패 0**. 두 변경은 충돌 없이 병합 가능함을 확인했다. 운영 main을 실제로 병합한 것은 아니다.
- 검사 범위: 검색어별 3/3/2 배분, 재시도 회복/지속 실패/403, 공식 URL과 ID 중복 제거, 실제 검색 강조 태그, 공고일과 마감/수정일 구분, 누락/오류/미래 날짜, 로그인/본문 없음, 검색 목록 구조 오류와 명시적 0건의 구분, R&D 표기 차이와 실질적 제목 불일치, 비출입처 단서 제외, 없는 금액 미생성.
- 초기에 공고금액 원문 공백(`425 억원`)을 없는 것으로 기대한 테스트 1건을 실제 응답에 맞게 수정했다. 추출 값을 임의로 바꾸지 않았다.
- 기존 DART 정규식 FutureWarning은 동일하게 발생하며 이번 범위에서 변경하지 않았다.

후보가 늘었다고 보고하지 않는다. 확인한 자료는 모두 오래돼 제외하는 것이 맞다. **8건의 정상 조회와 최근 자료 0건은 구별해서 기록했다.**

목록은 검색어별 첫 페이지만 조회했다. 철강 검색은 전체 21건 중 10건, 변압기는 7건, 전력망은 2건을 발견했다. 고유 URL 19개 중 11개는 상세 한도로 미조회했다. `coverageLimited=True`, `collectionComplete=False`이므로 NTIS 전체에 최근 자료가 없다고 단정할 수 없다. 실행 전후 루트 JSON 및 data.js의 SHA-256은 일치했다.

## GitHub 및 남은 작업

이번 변경은 독립 PR로 제출하며 main 병합·배포·운영 데이터 갱신은 하지 않는다. 기존 workflow는 pull_request 이벤트를 받지 않으므로 PR 생성 자체로 Actions 회귀 테스트가 실행되는 것은 아니다.

남은 사항: GitHub Actions 환경에서 간헐적 타임아웃 재현/빈도 확인, 첫 페이지·8건 한도 밖 자료, 첨부 문서, 검색엔진 색인 지연, 원문과 이전 공고 간 실질 변화 비교. 최근 공고가 없다면 억지 후보를 만들지 않는다.

다음 우선순위는 DART 수치 추출 실패의 유형별 분리·수정이다. 그다음 출입처 목록의 명시적 누락/추가 근거 정리, KIPRIS 공식 수집, 사건 단위 비교를 작은 PR로 진행한다. 배포 자동화 개선과 실제 화면 반영은 코드 검증과 별도로 다룬다.
