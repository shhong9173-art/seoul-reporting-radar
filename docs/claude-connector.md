선배 매의눈의 3층 구조(수집 → Claude가 부르는 도구 → 취재 절차 스킬)를 이 레이더에 맞춰 옮긴 것이다.

| 층 | 선배 매의눈 | 이 레이더 |
|---|---|---|
| 수집·대조 | 서버 프로그램 | GitHub Actions 수집기(기존) + `scripts/radar_tool_views.py`가 만드는 `tools/*.json` |
| 도구 | MCP 도구 43개 | Cloudflare 워커 `/mcp` (아래 16개) |
| 절차 | hunt·paper·desk·balje·gisa 스킬 | radar-hunt·radar-balje·radar-desk 스킬(기자 계정에 저장) |

## 주소와 권한

- 공개 연결: `https://seoul-reporting-radar.shhong9173.workers.dev/mcp`
  공개 자료(이미 GitHub Pages에 공개된 레이더 결과)만 읽는다. 구글 뉴스 대조, 원문 열기, 후보 점검 가능.
- 기자 전용 연결: `https://seoul-reporting-radar.shhong9173.workers.dev/mcp/<MCP_ACCESS_TOKEN>`
  DART 실시간·네이버 뉴스·나라장터 실시간과 비공개 저장소(취재 패키지·후보·판정 기록)가 열린다.
  토큰이 틀리거나 등록 전이면 404를 돌려준다.
- 저장소와 Pages는 공개다. 취재 패키지·킬 사유·후보는 저장소에 쓰지 않고 워커의 비공개 저장소(Durable Object, SQLite)에만 둔다.

## 원칙(코드로 강제)

- 조회 실패·미설정·일부 성공은 0건이 아니라 미확인으로 돌려준다. `news_check`는 채널별 상태를 따로 적는다.
- 뉴스 색인 0건은 `색인 0건 — 미보도 증거 아님`, 유사 제목은 `같은 사건인지 원문 확인 필요`로만 표시한다.
- 출처가 붙인 단계(공개 원자료 추적 / 취재 단서·단독 미확정 / 단독 후보)를 도구가 올리지 않는다.
- `candidate_check`는 원문 URL·게시일·내용 해시, 보도 3채널 조회, 이미 났나 판정, 질문 2~3개, 비교가 없으면
  `조사대기`로 돌린다. 제목 숫자는 원문 수치나 허용 계산 5종(증감률·차이·비중·합계·단위환산)만 통과.
- 점수(가점·감점)와 지면감(새로움·숫자·판·출입처·시점·확장·독점 0~2)은 정리용이다. 단독 판단은 기자가 한다.
- `source_document`는 공식 기관·DART·KIND·KIPRIS·.gov·EU·출입처 홈페이지만 열고 내용 해시를 준다.

## 설정(기자가 할 일)

1. 이 PR과 `tools/*.json` 생성 PR을 병합한다. main 병합 시 Cloudflare가 워커를 배포한다.
2. Cloudflare 대시보드에서 이 워커의 비밀값(Variables and Secrets)에 추가한다.
   - `MCP_ACCESS_TOKEN`: 32자 이상 무작위 문자열(영문·숫자·`-`·`_`). 기자 전용 주소의 열쇠.
   - `DART_API_KEY`: GitHub Secrets에 쓰는 것과 같은 OpenDART 키.
   - `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`: 네이버 뉴스 검색. 새로 받는 키는 네이버 클라우드 플랫폼 NAVER API HUB(Application 등록에서 '뉴스' 선택 → [인증 정보])에서 발급한다. 개발자센터 신규 신청은 막혔다. 서버는 HUB 방식으로 먼저 호출하고, 거부(401·403)될 때만 예전 개발자센터 방식으로 다시 호출한다.
   - `G2B_API_KEY`(또는 `DATA_GO_KR_KEY`): 공공데이터포털 일반 인증키.
3. Claude 설정의 커넥터에서 사용자 지정 커넥터를 추가하고 기자 전용 주소를 넣는다.

키 값은 응답·로그·저장소 어디에도 출력하지 않는다.

## 단독 후보 자동 심사(scoop_screen, 기자 전용)

- GitHub Actions `Scoop Candidate Screen`이 평일 07:10·15:10 KST에 레이더 단서(취재 단서 등급·최근 10일 비절차 공시)와 사업보고서 수치 변화(강도 60 이상)를 골라 네이버 뉴스 API·빙·구글로 기보도를 대조한다.
- 판정: 같은 수치 선행 / 관련 보도 있음 / 미보도 후보 / 미확인. 미보도 후보는 네이버와 웹 색인이 모두 정상 응답했는데 관련 기사가 없다는 뜻일 뿐 단독 판정이 아니다.
- 결과는 저장소에 커밋하지 않는다. `POST /ingest/scoop-screen`(Authorization: Bearer = MCP_ACCESS_TOKEN)으로 Durable Object에만 저장하고, 커넥터 기자 전용 경로의 `scoop_screen` 도구로 읽는다. 공개 로그에는 건수만 남긴다.
- 필요한 GitHub Secrets: `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, `MCP_ACCESS_TOKEN`(Cloudflare 값과 같게). 토큰이 없으면 심사는 돌지만 결과를 어디에도 저장하지 않는다.
- 기자가 `candidate_feedback`로 '킬'한 후보는 기본으로 숨긴다.

## 국내 신호(kr_signals, 기자 전용)

- GitHub Actions `KR Signals Watch`가 평일 08:30·15:20 KST(Cloudflare 요청, GitHub 예약은 예비)에 세 곳을 본다. 결과는 `kr-signals` 비공개 저장소로만.
- 공정위 의결서(case.ftc.go.kr, 열쇠 없음): 의결일 최근 120일 목록 → 처음 보는 의결서는 개방문서 전문을 읽어(실행당 최대 40건, 나머지는 다음 실행) 출입처·관련 기업 법인명이 피심인/발주처/사건명/본문 중 어디에 있는지와 주문 발췌를 남긴다. 이름은 통째로만 맞춘다(포스코 ≠ 포스코이앤씨, LS지주·GS는 법인 표기만). '발주처'는 제재 대상이 아니다.
- radar_today 등급: 출입처가 피심인이거나 과징금 납부기한 연장·분할납부 신청 → A, 발주처·사건명 → B, 본문에만 → C. 새로움은 파일 등록일(파일번호 앞자리) 기준.
- 한전 전자입찰(전력데이터개방포털 electContract, Secret `KEPCO_API_KEY`): 최근 14일 공고(한전·발전 자회사 등 전력그룹사) 중 **자재구매**의 전력기기·전선 품목(변압기·GIS·차단기·케이블·애자·리액터·STATCOM·ESS 등)과 HVDC·765kV급 공사. 감리·설계·연구·유지보수 용역은 뺀다. 추정가격 100억원 이상 B, 10억원 이상 C, 그보다 작으면 도구에서만. 공고 상태 변화(유찰 등)는 이벤트. 열쇠가 없으면 '미설정'(0건 아님).
- 산업통상부 보도·참고자료(motir.go.kr, 열쇠 없음): 최근 두 쪽(20건)에서 출입처 업종 낱말·출입처 이름이 제목에 있는 것. 첨부 파일명의 엠바고(조간·석간·시각)를 함께 적는다. 출입처 이름·무역위 판정·월간 수출입 동향은 B, 업종 낱말만은 C. '○년 ○월 수출입 동향'은 본문 주요 품목 표에서 자동차·부품·철강·비철·석유화학·석유제품·이차전지·전기기기·일반기계·선박 수출액·증감률을 적힌 그대로(표가 어긋나면 본문 문장에서).
- 원자재 가격(KOMIS, 열쇠 없음): LME 아연·연·동·알루미늄·니켈, LBMA 금·은, 철광석·원료탄·탄산리튬. 같은 가격 기준·단위만 비교하고, KOMIS가 2026-01-01 자료원을 바꾼 광종은 2026-01-05 이후만 본다. 신호는 '그 날(값) 이후 최고/최저 — N일 만'(90일 이상), 한 달 ±10%, LME 재고 한 달 ±25%. 같은 신호는 14일 안에 다시 올리지 않는다. 최고·최저는 B, 나머지는 C. '역대'는 판정하지 않는다.

## 주간 품질 점검(candidate_weekly_review, 기자 전용)

- `candidate_feedback`(씀·킬·보류·봤음)를 남길 때 그 항목이 어느 감시·종류(DART는 공시 종류, 예: 채무보증)·등급(A/B/C)·일상 판정이었는지를 비공개 저장소(`feedback_meta`)에 함께 적는다. 감시 결과가 다음 실행에 바뀌어도 묶음이 유지된다.
- `candidate_weekly_review`는 최근 N일 판정을 감시별·종류별·판정 때 등급별로 센다. 같은 항목을 여러 번 판정하면 마지막 판정만 센다.
- 점검 후보: 5개 이상 묶음에서 킬 60% 이상, 일상(B)·C(참고)로 내렸는데 '씀'인 항목. 기자가 볼 목록일 뿐 가중치·등급 규칙은 자동으로 바꾸지 않는다.
- 이 기능 전에 남긴 판정은 지금 감시 목록에서 찾아 표시를 붙이고, 목록에 없으면 '감시 미상'으로 둔다.
