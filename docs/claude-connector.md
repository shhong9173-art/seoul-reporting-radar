  `?hours=72`·`?q=회사`·`?minor=1`(참고 C). 스크립트 없음, Referrer-Policy no-referrer(바깥 링크로 토큰 주소가 새지 않게), noindex·no-store.
  홈페이지 로그인(11-01 기자 요청 "아이디 비번 넣고 로그인"): 워커 비밀값 `BOARD_USER`·`BOARD_PASSWORD`(Cloudflare에서 기자가 직접 등록 — 대화·저장소에 적지 않음). 탭의 로그인 상자 → `POST /auth/login`(text/plain JSON) → 30일 세션 `v1.<만료>.<HMAC(MCP 토큰|비밀번호)>`을 그 브라우저에 저장 → `GET /b/me`(Authorization: Bearer). 서버에 세션을 저장하지 않고 서명으로 확인하며, 비밀번호를 바꾸면 이전 세션은 모두 무효. 아이피별 1시간 8번·전체 1시간 40번 실패하면 1시간 잠금(실패 기록 Durable Object login_fail, 하루 뒤 지움). 비밀값을 등록하면 `/b/open`은 자동으로 401(공개 끝).
  사이트 첫 화면 잠금(11-01 기자 요청 "사이트 첫화면부터 로그인"): 루트 HTML 25개 `<head>` 맨 앞의 `gate.js`가 로그인 확인 전까지 화면을 가리고 로그인 상자를 띄운다. 세션이 있으면 워커 `GET /auth/check`(200 열림·401 다시 로그인·503 미설정이면 잠그지 않음)로 확인. 세션은 '오늘의 레이더'와 같은 localStorage 'radarSession'(30일). 한계: GitHub Pages는 정적 공개 사이트라 이 잠금은 화면만 가린다 — 공개 저장소의 자료 파일(scoop.json 등)은 주소를 알면 누구나 받는다. 기자 전용 단서(/b/me)는 워커가 세션을 확인해야 내준다.
  주의(11-01 운영): 기자가 Cloudflare 대시보드에서 BOARD_USER·BOARD_PASSWORD를 저장한 직후 워커가 #498 이전 코드로 배포돼 있었다(/r·/b·/auth/login이 홈페이지로 307, /mcp는 정상). 대시보드 저장이 예전 버전을 다시 배포한 것으로 보인다(원인 미확인). 비밀값을 바꾼 뒤에는 main을 다시 배포하고 /b/open이 401인지 본다.
  11-01 기자 결정(로그인 설정 전까지): 홈페이지 '단독감·미보도' 탭 맨 위 '오늘의 레이더'는 열쇠 없이 `GET /b/open` 조각을 불러온다(경쟁지 포함 누구나 볼 수 있다는 설명을 듣고 '열쇠 없이 공개'를 고름). CORS는 홈페이지 주소만, 같은 조건 조각은 한 실행 환경 안에서 60초 재사용. 아래 읽기 전용 열쇠 방식(/b/<열쇠>)은 남겨 두었지만 홈페이지는 더 쓰지 않는다.
  (이전 방식) 화면 맨 아래 '홈페이지에 연결'은 홈페이지 주소에 `#rk=<읽기 전용 열쇠>`를 붙여 연다. 열쇠는 MCP 토큰에서 HMAC('board-read-v1')로 뽑은 32자로, 이 화면 조각(`GET /b/<열쇠>`)만 읽힌다(커넥터·저장소 쓰기·수집기 전송 안 됨). 홈페이지 scoop.js가 주소 조각을 그 기기 브라우저(localStorage 'radarBoardKey')에 저장하고 지운 뒤, '단독감·미보도' 탭 맨 위 '기자 전용 레이더'에 조각을 불러온다(CORS는 https://shhong9173-art.github.io만). 탭 숫자는 연결한 기기에서 오늘의 A+B. '이 기기 연결 끊기'로 지운다. 열쇠를 바꾸려면 board.mjs의 BOARD_KEY_LABEL을 올린다(예전 열쇠는 바로 404). 주의: 같은 github.io 주소(shhong9173-art.github.io)의 다른 저장소 페이지도 같은 브라우저 저장소를 본다.
  토큰이 틀리면 404. 공개 홈페이지의 '단독감·미보도' 탭은 연결하지 않은 기기에서는 공개 수집기(scoop_scout) 결과만 보이고, 기자 전용 단서는 공개 저장소에 싣지 않는다(11-01 문의: 탭이 비어 보임 — 그날 scoop_scout 197건 중 출입처 밖 156·잡음 32·협회 페이지 8·기보도 1로 후보 0).

## 원칙(코드로 강제)

- 조회 실패·미설정·일부 성공은 0건이 아니라 미확인으로 돌려준다. `news_check`는 채널별 상태를 따로 적는다.
- 뉴스 색인 0건은 `색인 0건 — 미보도 증거 아님`, 유사 제목은 `같은 사건인지 원문 확인 필요`로만 표시한다.
- 출처가 붙인 단계(공개 원자료 추적 / 취재 단서·단독 미확정 / 단독 후보)를 도구가 올리지 않는다.
- `candidate_check`는 원문 URL·게시일·내용 해시, 보도 3채널 조회, 이미 났나 판정, 질문 2~3개, 비교가 없으면
  `조사대기`로 돌린다. 제목 숫자는 원문 수치나 허용 계산 5종(증감률·차이·비중·합계·단위환산)만 통과.
- 점수(가점·감점)와 지면감(새로움·숫자·판·출입처·시점·확장·독점 0~2)은 정리용이다. 단독 판단은 기자가 한다.
- `source_document`는 공식 기관·DART·KIND·KIPRIS·.gov·EU·출입처 홈페이지만 열고 내용 해시를 준다.

## 설정(기자가 할 일)

1. 이 PR과 `tools/*.json` 생성 PR을 병합한다. main 병합 시 Cloudflare가 워커를 배포한다.
2. Cloudflare 대시보드에서 이 워커의 비밀값(Variables and Secrets)에 추가한다.
   - `MCP_ACCESS_TOKEN`: 32자 이상 무작위 문자열(영문·숫자·`-`·`_`). 기자 전용 주소의 열쇠.
   - `DART_API_KEY`: GitHub Secrets에 쓰는 것과 같은 OpenDART 키.
   - `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`: 네이버 뉴스 검색. 새로 받는 키는 네이버 클라우드 플랫폼 NAVER API HUB(Application 등록에서 '뉴스' 선택 → [인증 정보])에서 발급한다. 개발자센터 신규 신청은 막혔다. 서버는 HUB 방식으로 먼저 호출하고, 거부(401·403)될 때만 예전 개발자센터 방식으로 다시 호출한다.
   - `G2B_API_KEY`(또는 `DATA_GO_KR_KEY`): 공공데이터포털 일반 인증키.
   - `SEC_USER_AGENT`: SEC EDGAR 원문(`source_document`의 sec.gov 주소)을 열 때 보내는 접속 표시. SEC 공개 접속 규칙대로 '회사·이름 연락이메일' 한 줄을 영문으로(예: `iNews24 이름 이메일주소`). HTTP 머리글이라 한글이 섞이면 보낼 수 없어 쓰지 않고 안내한다. GitHub Secrets의 같은 이름 값(해외 파트너 공시 감시가 씀)과 같게 둔다. sec.gov에만 보내고 다른 곳에는 보내지 않는다. 없으면 SEC가 HTTP 403을 줄 수 있고, 도구가 '비밀값에 없음'이라고 알려 준다(10-31 운영: 퍼스트솔라 10-Q 403).
3. Claude 설정의 커넥터에서 사용자 지정 커넥터를 추가하고 기자 전용 주소를 넣는다.

키 값은 응답·로그·저장소 어디에도 출력하지 않는다.

## 출입처 외신(radar_today 안, 기자 전용 감시 24번째)

- 외신 수집(global_collector.py, 뉴스 수집 20분마다)이 구글 뉴스·매체 RSS 외신 가운데 **직접 출입처 이름**이 나온 기사만 기자 전용 저장소 `global-beat`로 보낸다. 출입처 판정은 AGENTS.md 목록만, 계열사·부분 일치 제외(포스코퓨처엠·포스코인터내셔널·HD현대중공업·현대엔지니어링·두산밥캣 등은 아님), 긴 이름 먼저.
- 한국어 제목에 사건 낱말(원자로·해상풍력·해저케이블·변압기·모노파일·제련소·관세·리콜·소송·수주·공장·투자·MOU·입찰·인수·파업·감산·ESS·태양광·철강·배터리·타이어 — 회사 이름에 든 낱말 제외)이 있으면 **B**(평일 08:50·18:50 자동 보도 대조 대상, 검색어=출입처+사건 낱말), 없으면 참고(C). 첫 수집에 잡힌 기존 기사는 게재일이 최근일 때만.
- 11-01 석유화학·정유 6곳: 검색 묶음 '출입처·석유화학정유'(LG Chem·Lotte Chemical·Kumho Petrochemical·S-Oil·SK Innovation·Hyundai Oilbank), 출입처 판정(현대차 규칙은 Hyundai Oilbank를 뺀다), 번역 표기(S-Oil→에쓰오일 등), 사건 낱말(구조조정·나프타·정제마진·석유화학), 외신 매체(Hydrocarbon Processing·Chemical Week·Oil & Gas Journal·Energy Intelligence·OPIS).
- 11-01 바로잡음: 석유화학·정유 검색 결과가 업종 낱말(refining·naphtha cracker 등)이 없다고 모두 점수 없음으로 빠지고 있었다 — 업종·출입처 낱말을 더하고, 출입처 이름 검색은 출입처 이름이 있으면 점수가 없어도 둔다. 점수 상위 60개 밖의 출입처 외신도 최신 20개까지 따로 번역·저장한다(일반 자동차 외신에 밀리지 않게).
- 제목·요약은 AI 번역·요약이라 원문 확인(11-01 운영: 한수원 체코 요약에 '대우-두산 컨소시엄' — 국내 보도는 '대우건설 컨소시엄'). 외신 화면에 '출입처만' 거르기.
- 숫자 대조(scripts/number_check.py): AI 번역 제목·요약의 숫자('4억 5천만 달러'·'1조9천3백억 원'·'92만 710대')를 값으로 바꿔 AI가 받은 영어(제목·구글 설명·매체 RSS 발췌, 'US$450m'·'KRW1.93trn'·'920,710'·'three'·'Oct.')에서 같은 값(반올림 0.6%까지)을 찾는다. 못 찾은 숫자는 `numbersNotInSource`로 남기고 레이더(`⚠ 원문 발췌에 없는 숫자`)와 외신 화면에 표시 — 지어낸 숫자, 원화 환산·계산한 숫자, 표기가 달라 못 맞춘 숫자 모두 해당하므로 오류 확정이 아니라 원문 대조 신호. 기사 발행 연도는 '올해'를 옮긴 것으로 보고 허용.
- 기사가 아닌 글은 수집 단계에서 뺀다: 팟캐스트·웨비나·스폰서·'available now on'·할인(pre-order/launch/best/green deals)·쿠폰, '2027 Hyundai Ioniq 5'처럼 연식+차종 이름뿐인 판매 페이지(11-01 운영). 계약(deal)·매각(for sale)·가격 기사는 남긴다. 차 판매 중개 사이트 EV.com은 외신 화면에만, 레이더로는 안 보냄.

## 단독 후보 자동 심사(scoop_screen, 기자 전용)

- GitHub Actions `Scoop Candidate Screen`이 평일 07:10·15:10 KST에 레이더 단서(취재 단서 등급·최근 10일 비절차 공시)와 사업보고서 수치 변화(강도 60 이상)를 골라 네이버 뉴스 API·빙·구글로 기보도를 대조한다.
- 판정: 같은 수치 선행 / 관련 보도 있음 / 미보도 후보 / 미확인. 미보도 후보는 네이버와 웹 색인이 모두 정상 응답했는데 관련 기사가 없다는 뜻일 뿐 단독 판정이 아니다.

- 주생산품·업종은 쉼표 등으로 나눈 항목 집합으로 비교한다. 순서·띄어쓰기·끝의 '등'만 다르면 변화가 아니다(운영 10-29: LS일렉트릭 청주1공장 주생산품이 순서만 바뀐 것이 A로 떴다). 주소는 괄호 안 참고 항목(동·건물명)과 띄어쓰기를 빼고 비교한다.

## 주간 품질 점검(candidate_weekly_review, 기자 전용)

- `candidate_feedback`(씀·킬·보류·봤음)를 남길 때 그 항목이 어느 감시·종류(DART는 공시 종류, 예: 채무보증)·등급(A/B/C)·일상 판정이었는지를 비공개 저장소(`feedback_meta`)에 함께 적는다. 감시 결과가 다음 실행에 바뀌어도 묶음이 유지된다.

- 이 기능 전에 남긴 판정은 지금 감시 목록에서 찾아 표시를 붙이고, 목록에 없으면 '감시 미상'으로 둔다.
