# 정정 공시 전후 표 추출 — 2026-10-12

## 범위와 근거

main `8aafac0a930d30d69cdb0a84e6aab7f1080166c3`에서 분기했다. 기존 코드는 정정 공시를 신규 사건에서 제외하고 공개 추적 항목에 ‘변경 항목 대조 필요’라고만 표시했다. 정정표에 명시된 전후 사실을 보존하는 첫 단계다. 최초 공시 원문을 별도로 조회·대조하는 비교 엔진이 완성된 것은 아니다.

공식 정정 원문의 `정정항목 / 정정전 / 정정후` 또는 `항목 / 정정사유 / 정정전 / 정정후` 표를 읽는다. 제목 유사도로 별개 사건을 연결하지 않으며 원공시 ID·URL을 만들어내지 않는다. `basis=issuer_correction_table`, `originalDocumentVerified=false`로 기업이 정정표에 기재한 비교임을 명시한다.

## 변경 파일

- `dart_corrections.py`: HTML 표 파서, 전후 셀 비교, 생산 일정·금액·상대방·계약 기간·생산능력·형식 변경·문구 검토 구분, 공개 추적용 설명 생성.
- `dart_numeric_extractor.py`: 공개 HTML 뷰어 및 OpenDART ZIP 문서에서 비교 결과를 수치 결과에 함께 보존한다. ZIP 출처에는 API 키가 포함된 요청 주소 대신 실제 접수번호의 공개 DART 링크를 기록한다.
- `scoop_scout.py`: 기존 공개 원자료 추적 영역의 details에 전후 문구를 표시한다. 기존 직접 출입처·공개일·자사주 제외 및 정정 공시 단독 억제 기준을 유지한다.
- `tests/correction_cases.py`, 기존 테스트 진입 파일, 실제 HTML fixture 3개: 회귀 검증.

공백 차이만 있는 값은 변경에서 제외한다. 누락 셀·중첩 표·병합 셀은 추측하지 않는다. 이전 값의 `-`는 0이 아니라 미기재 상태로 보존한다. 금액 단위를 추측하거나 차액을 자동 계산하지 않는다. 정정일과 정정 대상 자료의 제출일은 별도 필드로 기록하고, 없는 날짜를 조회일로 채우지 않는다. referencedFilingDate가 최초 공시일이라고 단정하지 않는다.
