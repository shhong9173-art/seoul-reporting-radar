# 공식 증거 등급별 취재 대기열

시작: reporting-queue.html, 원천 스크립트: scripts/reporting_evidence_queue.py, 운영 데이터: digests/reporting_evidence_queue_latest.json.

## 이 기능이 해결하는 문제

- DART 수집 시각이 새로운 공시 발생일이 아님. 실제 문서 접수번호 앞 8자리 및 문서의 공식 날짜만 분류에 사용한다.
- 신규 공식 접수란 이미 대중에 공개된 접수이지 단독 보도가 아니다. 문서 내용·기업 영향·기보도는 각각 별도 검증.
- 과거 두 DART 사업보고서 간 동일 사업 투자 종료 예정월의 차이는 계획의 기재 변화. 공장 실제 지연, 생산 물량/가동일, 재무효과는 미확인.
- 동일 행·표모수·단위·전년 및 당년 공시 숫자 차이는 현물 출하량 증가와 다르다.
- 계약 정정문 자체의 전후 변경란은 원공시를 직접 대조한 자료가 아니다. 원공시 접수번호가 미확인인 정정은 원문 대조 대기열에만 배치.
- 같은 DART 공식 접수번호의 새 공시가 원문·계약 자료 양쪽에 등장해도 중복 신규 후보를 만들지 않는다.
- 원천 파이프라인이 미수집·지연·부분수집일 경우 0건 발견을 0건 존재로 해석하지 않는다.

## 출고 전 필수 취재
각 항목의 공식 URL을 직접 확인하고 실제 금액·법인·사업·보고 연도·원/정정 공시 식별, 다른 언론의 기존 기사 **전문** 대조, 회사에서 공유 가능한 확정·공개 사실 확인이 필요하다. 보도자료·공시 제목 재진술만으로 발제 승인하지 않는다. 제조사의 내부 영향 검토·미래 생산/조달/계약·미확정 정책 대응에 관한 홍보팀 질문은 자동 추천하지 않는다.

## 운영
GitHub Actions Evidence-first Reporter Queue는 평일 10시/14시/18시(KST) 및 코드 병합시 실행한다. 입력원은 공식 원문 비교·계약 후속·당일 공보 분류 등 기존 GitHub digests이며 새로운 API 키는 사용하지 않는다. Python와 Node 회귀검증 및 실제 저장된 원천 재생 성공 시에만 자료를 main에 게시한다.
