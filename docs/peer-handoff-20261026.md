## 적용하지 않는 원칙

- 검색 0건만으로 '단독 확실'을 부여하거나 온라인 미발견을 지면 미보도로 간주하지 않는다.
- 선배 지면 DB가 없으므로 지면 톱 등급·기사 ID·실측 문체 통계를 새로 확인한 결과처럼 만들지 않는다.
- 식품팀의 CJ 가점과 소비자 영향만을 산업부 기업에 그대로 적용하지 않는다.
- 특허 공개를 개발 착수·상용화 확정으로 바꾸지 않는다.

## 이번 구현과 검증

- 메모는 기존 후보 ID별로 분리하고 다른 기기에 자동 동기화하지 않는다. 서버나 공개 저장소에 취재 메모를 전송하지 않는다.
- 실제 발제함/추가 취재 필요/이미 보도됨/출입처 아님/가치 낮음/원문 오류를 기록한다. 기자 기록은 자동 점수·단독 판정과 분리한다.
- 잘못된 백업·중복 ID·길이 초과·저장 실패는 기존 기록을 보존한다. 복원 시 동일 항목은 최신 기록을 유지한다.
- 문서 묶음은 URL의 앵커·utm만 정규화한다. 서로 다른 DART 접수번호를 합치지 않는다. 같은 문서라는 사실이 같은 사업장·사건임을 보증하지 않는다.
- 미래 수집 시각을 최신 정상 수집으로 표시하던 조건을 수정했다.
- Node 신규 취재 기록/문서 묶음 회귀와 기존 후보 화면 회귀 통과. 공식 수집기 Python 95개 통과.
- 로컬 브라우저에서 별·메모·처리 상태 저장, 새로고침 후 유지, 별 표시 필터를 확인했다. PR 검사와 운영 배포는 별도 확인한다.
- 이번 기능으로 새 단독이나 신규 취재 단서를 발굴했다고 주장하지 않는다. 기존 근거의 검토·기록 기능 개선이다.

## 후속 우선순위

1. 후보 한 건의 원문 재조회·해시 비교·채널별 선행보도 조회 결과를 실행 ID에 연결. 실패하면 심사 대기.
2. 공시 비교에 원가율·직원 수 추가. 연결/별도·누적/분기·기준일 불일치를 차단.
3. 같은 사업장·프로젝트의 문서 간 연결을 원문 식별자와 명시된 관계로 확장.
4. 동일 기간 통계의 엇갈림·순위 역전과 발표 캘린더. 표본 범위 밖의 '역대' 표현 차단.
