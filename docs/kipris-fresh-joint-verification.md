# 최근 3일 공동특허 취재 검증 (KIPRIS 공식자료)

## 발굴 원칙

산업부 출입처(현대차·기아·부품·철강·전력기기·에너지)의 KIPRIS 공개특허 중 출입처 외 **기업·대학·연구기관이 공식 공동출원인으로 명시된 공개번호**를 단서로 봅니다.

- 공식 KIPRIS 공개일(출원일·등록일과 구분) 기준 최근 한국시간 3일을 우선합니다. 검색을 수행한 날짜보다 이전 공개일에 이미 언론이 보도했다면 신규 단독 근거가 아닙니다.
- 전체 공동출원 1개 공개번호는 하나로 묶습니다. 출입처 밖 공동출원인은 법인명 그대로 구별하며, 동일 그룹 기업 간 출원과 이종 산업 공동출원은 서로 다른 신호입니다.
- 기존 deep 출력에서 공동출원 82개 중 상위 30개만 노출하던 절단을 없앴습니다. 이전 스냅샷은 여전히 30건만 담겨 있으므로 **전체 82개 최근 확인 완료인 것처럼 표시하면 안 됩니다**. 수집기 재실행 후 원본에서 전체 후보를 내보냅니다.
- 청구항 제1항은 공개된 서지상세와 **그 출원번호의 공식 원문이 일치**해야 검증 표시합니다. 문구만으로 법적 신규성·진보성·세계 최초를 판단하지 않습니다.
- 동일 제목 과거 공보는 2023년 이후 제한적 조회이며 다른 제목 선행문헌, 해외 패밀리, 의견제출·보정 이력은 남습니다.
- 구글뉴스 RSS의 색인검색 결과 0개는 **미보도 입증 아님**. 오래된/미수집/불확실한 검색 상태를 구분하고, 회사 발표·전문지·기사 원문은 별도로 확인합니다.
- 실제 적용 차종, 생산라인, 시제품·양산·수주, 기술적 역할, 계약과 제품 성능 개선 수치는 회사 답변 및 독립 자료가 없으면 미확인입니다.

## 구현

- `scripts/patent_deep_hunt.py`: 공식 외부 공동출원 특허를 전체 조사서에 내보내고, 공개번호 하나를 중복 후보로 세지 않음.
- `scripts/patent_joint_verification.py`: 공식 수집·심층·기사색인·청구항 리뷰의 **서로 대응되는 소스 스냅샷**을 검사. 최근 3일과 과거 참고 자료를 별도 목록에 놓고, 공개번호·출원번호·청구항 원문·이종 산업 공동출원인·기보도 검색 상태를 결합. 제목과 기술어 일치만으로 사업화 연결하지 않음.
- `patent-joint-verification.html`: 읽기 전용 취재 검증 페이지. 원자료가 24시간 넘으면 이를 명확히 표시하며 신규 0건이라고 단정하지 않음. 3일 구간의 공동출원 결과가 없더라도 오래된 데이터를 최신 기사거리로 둔갑시키지 않음.
- `.github/workflows/kipris-patent-hunt.yml`: 기존 KIPRIS 승인 API Secrets를 통한 공식 수집 다음에만 새 검증 자료 생성. 어떤 단계든 실패 시 이전 정상 데이터 보존. 개별 신청 키를 저장·전달하지 않음.
- `.github/workflows/patent-joint-verification-ci.yml`: 네트워크 없는 회귀테스트로 소스 일치·미조회 상태·미보도 단정 금지·청구항 번호 오류 차단.

## 실제 부장 보고 전 검증

**청구항에서 무엇이 달라졌는지 → 출입처 회사가 실제 어디에 적용하는지 → 적용 또는 미적용의 규모·사업 변수 → 관련 기존 보도 및 회사 답변 → 기자 주장(야마)**의 순서로 확인합니다. 공식 출원만 확인됐다면 화면에서도 '취재 검증 후보'이며 기자 보고용 확정 발제가 아닙니다.

언론 검색, 청구항, 회사 사업 현황 중 하나라도 미검증이면 시스템은 단독기사를 확정하지 않습니다. 화면 점수나 목록 노출은 기사 승인 신호가 아닙니다.
