# 주말 최신 DART 원문·본문 기재사항 취재 대기열 (2026-10-17)

## 기존 문제
'원문 증거 대기열'은 평일 한국시간 10·14·18시에만 재생성되고 있었다. 10월 17일 토요일에도 공식 DART 모니터는 17:41에 48개 출입처를 검토했으나 취재 대기열은 10월 16일 18:26에 멈춰 있었다. 공식 광역 사건분류가 NHTSA 등 일부 원천 누락으로 부분 수집이면 최근 접수 0건으로 보이는 문제도 있었다. 소스 스냅샷 누락은 신규 공식사건 0건을 의미하지 않는다.

## 개선
- 증거 대기열 갱신을 **토·일 포함 매일 10:00, 14:00, 18:00 KST**로 변경. 이미 수집한 공식문서만 읽기 때문에 외부 API 요청 증가는 없다.
- 추가 원천 digests/dart_beat_monitor_latest.json을 읽는다. 같은 법인·접수번호·DART 공식 링크·공식 본문표 필드가 검증된 **최근 3일 공개 계약**만 본문 기재사항으로 노출한다.
- 계약명 및 계약금액은 반드시 같은 공시 문서의 행 증거 basis=same_official_table_row여야 한다. 문서 본문을 읽지 못했거나 정정 문서의 원문 연계가 없으면 이번 신규 원문 근거로 표시하지 않는다.
- 계열사 상대 계약은 계열사 계약임을 명시한다. 외부 고객 신규 수주, 실제 출하, 최종 수익 인식, 독점 보도라고 절대로 주장하지 않는다.
- 동일 접수번호가 광역 공식 이벤트와 DART 상세 원문에 중복 발견되면 **공식 표 근거가 많은 상세 원문 카드 하나**만 보여준다.
- 기존 장기 비교(8월 투자표 변화 등)는 기본 화면에 나타나지 않는다.
- 뉴스/단독 자동수집이 별도로 GitHub main에 커밋해도 대기열 최신 산출물은 독립 임시 worktree에서 검증 후 게시한다. 기존 git pull --rebase 충돌을 사용하지 않는다.

## 검증
- 본문 원문 필드가 실제 source record 와 일치할 때만 새 원문 검토 카드로 승격.
- 외부수주 판단 및 미보도 판단은 항상 false.
- 동일 접수번호 중복 제거, 날짜 3일, 허위 URL, 비공식 필드 추론 거부.
- GitHub bare remote를 사용하는 atomic queue publisher의 거짓 단독 산출물 게시 거절 테스트.
- GitHub Actions에서 실제 저장 digests 전체로 재실행해 신규 기본 화면과 이전 자료 분리를 확인.
