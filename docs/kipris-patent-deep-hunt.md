# 공식 특허 '단독 탐색' 2단계: 과거 특허 이름 대조

## 2026년 10월 13일 최초 실데이터

KIPRIS 인증과 24개 출입처 검색 연결은 실제 성공했다. 첫 실행: 출입처 24개, 정상 결과 완료 22개, 현대자동차(총 282건)와 기아(총 284건)는 페이지 제한 2×100 때문에 잘렸다. 기술 키워드로 후보 161개를 표시했으나 당시 공개공보 자료는 80개로 잘려 저장됐다. 현대자동차·기아 공동출원 공보(예: 1020260148128)를 **서로 다른 두 건**으로 표시하는 오류도 있었다.

## 수정

- `scripts/patent_hunt.py`: 출원인당 최대 4페이지(페이지당 100건), 정상 API 총건수와 실제 조회된 수 검증, 모든 관련 공보는 최대 500건까지 보존. 추가 호출은 속도를 조절한다.
- `scripts/patent_deep_hunt.py`: 동일 공개번호를 하나의 공보로 병합, 공동 출입처를 표시한다. 같은 공개번호에 제목·공개일이 충돌할 경우 *제외*하고 이상 건수에 기록한다.
- 기술구분 교정: 차량 내부 DC/DC 변환을 자동으로 계통 HVDC로, 일반 차량제어 특허를 자동으로 레벨3 자율주행/SDV로 분류하지 않는다. 제목·초록만으로 확정하지 않는 기술적 용도는 '미확인' 표시.
- 기존 공개 데이터 최근 35일 내 제목 유사 공보 링크(기술/패밀리 동일성 미확정)를 분류.
- 우선 검토 공보 최대 10건에 대해 KIPRISPlus 공식 `getAdvancedSearch`의 `inventionTitle` + `openDate=20230101~개별공개전날`로 이전 공개공보를 검색한다. **동일 제목만 확인**하며, 다른 명칭의 선행특허, 청구항 구성, 해외 특허패밀리, 권리 상태·실제 적용 여부는 조사하지 않은 것으로 남긴다.
- 기사 야마에 필요한 취재 질문: 1항 청구항 구성은 종전 기술과 무엇이 다르며 어떤 제품 적용과 연결되는가? 회사 답변·발명자·기술 사업부·선행 보도·해외 패밀리 검증 후 발제.
- 세부 출처인 `patent_hunt_latest.json`과 심층 결과인 `patent_deep_latest.json` 생성 시각이 다르면 화면에서 숨겨 잘못된 데이터 연결 방지.
- `patents.html`은 조사 우선순위 공개번호 기준 18개로 표시하고 출원인 공동 명의·이전 동일 제목·최근 유사 제목·확인되지 않은 사항을 나눠 제공한다. 단순 특허 목록은 35개만 화면 출력해 대량 스크롤 방지.
- 평일 09:15 KST 기준 24개 출원인 조회 후 2단계 공식 조회(최대 10건) 수행.

## 한계와 다음 단계

이번 단계는 '특허 단독 3건'을 보장하지 않는다. 청구항 변경이 기재된 별도 KIPRISPlus 상세 API의 승인·스키마 확인 후 독립 청구항을 비교할 수 있으며, 그 전에는 '신규 청구항 기술'이라고 단정할 수 없다. 공식 특허패밀리 API/우선권 연계, 보도매체 내용 검증, 회사 직접 취재가 최종 기사 판단에 필요하다.

특허의 '신규 관측'은 모니터에서 새로 처음 발견했다는 뜻일 뿐 최초 출원·첫 공개/제품 양산·등록과 동치가 아니다.
