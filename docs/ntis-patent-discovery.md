# NTIS 국가R&D 성과검색 — 특허명·기술어·법인 출원인 교차검색

## 왜 새 검색이 필요한가

2026-10-14 승인된 Windows PC에서 KIPRIS 출원번호 **7개를 7/7 정상 조회**했으나, 성과검색 `TOTALHITS=0`이었습니다. 이는 NTIS 성과검색이 해당 출원번호를 현재 검색 방식으로 색인하지 않았을 수 있다는 **제한적 결과**입니다. 특허의 국가R&D 연계가 없다는 판정이 아닙니다. 같은 날 '부분방전' 기술어 검색에서는 197건의 검색 결과가 있었습니다.

2024-01-03 공식 NTIS 성과검색(전체용) 매뉴얼의 `rpatent` 응답 필드 `RegistNumber`는 출원번호와 등록번호를 모두 담을 수 있습니다. `RegistType=출원` (코드 `01`)으로 확인한 **KIPRIS 출원번호**만 직접 대조합니다. `ProjectID`는 국가과제번호, `ResultID`는 NTIS 성과 식별자입니다.

## 실행: NTIS 승인 PC

동일한 폴더에 다음 두 파일을 저장합니다.

- `scripts/ntis_patent_discovery_pc.ps1`
- `scripts/Run_NTIS_Patent_Discovery.cmd`

`Run_NTIS_Patent_Discovery.cmd`를 더블클릭한 뒤 기존 성과검색 승인 API 키를 **숨김 입력란**에 직접 입력합니다. GitHub나 채팅에 키를 넣지 않습니다.

기본 실행은 KIPRIS 출원번호가 별도로 확보된 특허 최대 7건을 대상으로 공식 자료에 근거한 검색식 최대 21개를 조회합니다. 검색 모드 우선순위는 ① 특허명에서 추출한 **기술어** ② **공식 특허명 일부** ③ KIPRIS 공동출원인 중 **법인명**입니다. 동일 특허에 대해 세 방식 모두 확인하려면 최대 21개 검색식이 필요합니다. 대량 호출을 피하기 위해 기본 21개를 실행하되, 한 번에 21개 검색식과 첫 페이지 10건으로 호출 상한을 제한합니다.

각 검색식은 **첫 페이지 10건**만 조사합니다. 일부 검색어의 `TOTALHITS`가 197건이더라도 앞의 10건만 확인하면 나머지 187건은 아직 조사하지 않았다는 사실을 표시합니다. 검색 결과가 많고 더 조사할 필요가 있을 때만 PC에서 `-MaxPages 2` 또는 `3`으로 제한을 높입니다. 확인하지 않은 페이지나 결과를 '불일치'라고 판정하지 않습니다.

성공하면 같은 폴더에 **`ntis_patent_discovery_pc_latest.json`**이 생성됩니다. 해당 JSON을 직접 열어 비밀키나 개인 정보가 없는지 확인한 뒤 이 대화에 첨부합니다.

## 기사거리 발굴을 위한 증거 단계

- **검색 반환수:** 키워드·발명명칭·법인명이 NTIS 색인에서 나온 횟수일 뿐, 특정 특허 성과가 아닙니다.
- **공식 출원번호 일치:** 같은 NTIS HIT에 `RegistType=출원`과 정확한 KIPRIS 출원번호가 있는지 검사합니다. 다른 등록번호나 공개번호는 비교 대상에서 제외합니다.
- **공식 과제번호 일치:** 같은 성과 HIT의 `ProjectID`가 앞서 NTIS 과제검색으로 수집한 26개 **일부 표본**에 있으면 우선 조사후보로 분류합니다. 표본에 없다는 이유로 국가과제 연계가 없다고 판정하지 않습니다.
- **회사 실무·사업화 검증:** 정확한 번호가 일치하더라도 해당 국가과제의 수행기관·연차별 기록·기보도·제품 적용·양산 여부는 기자가 별도로 확인해야 합니다. 자동 단독 확정은 **0건**입니다.

공식 매뉴얼과 실측 응답의 데이터 구조가 다르거나 권한·IP 문제로 실패한 조회는 '0건'으로 간주하지 않습니다. API 키·전체 비밀키 포함 요청 URL·관계없는 특허 성과 행은 출력 JSON에 저장하지 않습니다.

## 오프라인 회귀 검증

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\ntis_patent_discovery_pc.ps1" -SelfTest
```

GitHub Actions `NTIS Outcome Windows PC Regression`은 Windows PowerShell 5.1에서 공개 KIPRIS/NTIS 수집본을 사용해 실제 검색계획 생성, 합성된 출원·등록·무관특허 XML 3건에 대한 판별, JSON 생성 및 중복 제거를 검증합니다. 합성 테스트의 번호 일치는 **실제 NTIS 발견 건수가 아닙니다**. 실제 API는 사용자가 등록한 PC에서만 호출합니다.

`scripts/ntis_validate_patent_discovery.py`는 PC에서 생성된 JSON을 GitHub에 반영하기 전에 공식 번호·쿼리·데이터 스냅샷·비밀키 유출·과장된 검증 주장을 검사합니다.
